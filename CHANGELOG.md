# Changelog

## Unreleased

- **Attachment rows no longer pile up:** a round you leave, on a round's page or the past-decisions page, lets go of its attachments' rows, and its open boxes draw them again when you come back (from the box's top), with every note, typed and not yet saved ones too. Before, each big round visited kept its rows, so the memory grew with every such round. Now it holds up to about two rounds' worth until Chrome frees the dropped rows on its own, within about 30 seconds in headless Chrome.

- **A picker in `/config`, and the Claude Code floor:** Waiting hint is now a picker in `/config`. A Claude Code before 2.1.271 no longer loads the plugin.
- **Over SSH or in a devcontainer:** `--port <n>` on a run or `--history`, or the `SIGNOFF_PORT` environment variable (the flag wins; it also sets the inbox's port, kept in `inbox.json` as before), puts Signoff on one port you choose (1024 to 65535), so a tunnel (`ssh -L`, `LocalForward`, VS Code's Ports tab) is set up once instead of for every run. It still listens on `127.0.0.1` only, and the port stays random unless you set one: any process on the machine can take a free port first, and a page served there can leave a service worker in your browser that sees later Signoff pages on that port (see `docs/security.md`: pick a port no other web app has used in that browser). A bad value exits 1 with one line on stderr and nothing on stdout; so does a port another program listens on, which Signoff looks for with a connection to `127.0.0.1:<port>` before it binds (best effort; on macOS it also catches a listener on every address), and an `inbox serve` that stops there leaves no `inbox.lock`. In an SSH session (`SSH_CONNECTION` or `SSH_TTY` set) with no `BROWSER` set (VS Code's Remote - SSH terminal sets one that opens the link on your computer) a run and `signoff inbox open` open no browser and print the start link, as with `--no-open`, with the `no browser opened` line the agent hands you the link on. `signoff inbox open` on a taken port now says the inbox did not start at once, not after 15 seconds. Open the link with `127.0.0.1`, as printed: a browser may try `localhost` as `::1` first. The page, the inbox and the past-decisions page now also answer to `localhost:<port>`, as a forwarded port is often opened; a save must then come from that same name (`Origin`), and every other host name or port, and a request with two Host headers, gets 403. The start link Signoff prints stays `http://127.0.0.1:…`. Known limit: over SSH a row in the mod's panel opens nothing you can see, as on a machine without a browser. On Windows Signoff no longer sets `SO_REUSEADDR`, which there would let a second program bind the same port. `docs/running.md` has the steps.

- **The mod in the desktop app and VS Code:** tried on macOS in the desktop app's Code tab and the VS Code extension's own panel. The line above the prompt, the panel, the notice and the status line show there, and the mod ran Signoff's command (`signoff inbox home`); the README's table says so. Both send `session.start` as not interactive, so the mod starts looking at the band's first drawing, as it already did after a reload. No code change.
- **`/signoff:demo` and README notes:** `/signoff:demo` (the model never starts it, only you typing it) writes a small synthetic round in a temporary folder outside your project, runs Signoff on it, and gives you the command to remove the folder. Both READMEs now say to use Claude Code from the stable channel or newer, and that auto-update is off by default for a third-party marketplace; the README's browser table says Safari and Firefox were tested on macOS (a Done from the inbox page).
- **Unticking every recommended option is an answer:** a recommended many item whose every option you unticked now counts as answered: the panel no longer lists it.
- **A phone's first screen:** on a phone in Focus, an item now reads its question, the agent's recommendation and cost, its commands, then its pictures as thumbnails (a tap opens one full size), so the first option shows without scrolling. A picture you can mark starts small beside its caption, and **Larger** gives it the full width to draw on (**Smaller** takes it back). On a phone, in Focus or not, the header keeps the title beside the project's mark, with its buttons on a row below and no progress pill (the bar says which round waits), and the bar at the foot takes two rows (three when the save state needs a line of its own, as after a reload). On wider screens the opening time also sits on a line of its own, and when the round's title would get less than 260 px, the header's buttons move to a second row, right-aligned, instead of squeezing the title.
- **One-line fields in the Markdown copy:** a title, group, option label, unit, caption or attachment name holding a CR, U+2028, U+2029, NEL, VT, FF or FS/GS/RS character no longer splits its heading or list line in the copy; each such break shows as a space. Rounds with such text still load.

- **A round's age:** a round's page says when the round was asked (`Opened <date> · 3 days ago`) under the project's name in the header, from the round file's time, which a new run on the same rounds keeps. An open round 2 days old or more also says **Open 2+ days** there and, at the top of the round, that its questions may be out of date; its row in the inbox gets the same words, and its open row says how long. The row's time and order still follow the run's start. No file format changes.
- **A todo file of your choice:** a `todo` key in a project's file in the Signoff home (`projects/<id>.json`) names the project's todo file, a path relative to its root, for projects that keep their list in another file than `_bmad-output/todo.md`, `TODO.md` or `todo.md`. That file alone is then read, and it must be a file inside the root (links followed); otherwise the inbox lists the project with a fixed error and reads none of the three. The hooks never write the key; you add it by hand, as `docs/inbox.md` says. Without it nothing changes.
- **Done per round:** the `signoff` skill tells the agent that, when it can act on one round before the user answers the others, it may run each round alone in the background (`signoff <folder>/round-NN.json`); each run wakes the agent at its own Done, and a round that depends on another's answers is run alone too while others of the folder are open. No code change.
- **No App button:** the panel's rows no longer have an App button, and the mod no longer reads the app's `Info.plist`; each row opens its question in the browser, as before. `signoff inbox open --app` is gone (a usage error now, exit 1, with nothing run), and so are the control socket's `app_target` and `app_open`: they get the unknown-request reply. The macOS app no longer asks the inbox for a question when it comes up; it shows its window as a Dock click does. An app from 0.4.0 gets no link for `app_open` and does the same, and a 0.4.0 `signoff inbox open --app` still brings the app up, with no question.
- **Answered starts closed:** in the inbox list (and the macOS app), the Answered section is closed behind its heading, as a To do group is: a click opens it, a search opens it while a match is in it, a project picked in the sidebar opens it with that project's rows, and the page's own reload keeps it as it was. Its rows are out of j, k and Focus while it is closed.
- **SIGTERM and SIGHUP stop a run as Ctrl+C does:** a run or a waiter that gets either (from a closed terminal, say) now marks its entry in the Signoff home's `runs/` ended, lets go of its round locks, says `stopped` on stderr and exits 130, with nothing on stdout. Before, it died at once and left its entry without `ended`, so the inbox had only its process id to go by, which another process may get. Not on Windows, where a stopped process gets no signal it can catch; a signal ignored at the start, as under `nohup`, stays ignored; `--history` and the `signoff inbox` commands are as before.
- **A project without git:** a folder that holds a `.signoff` folder is now a project root, as a folder with `.git` is, the nearer one winning. A session started in such a project's own folder was not noted, so the inbox showed no session row, band or todo for it, and a decisions folder outside its `.signoff` got no project name on the page. In a git repo with a `sub/.signoff/` folder, a session started in `sub` now belongs to `sub`, as the decisions under `sub/.signoff/` already did, not to the repo, and so does a decisions folder elsewhere under `sub`: its band counts `sub`'s rows, the inbox reads `sub`'s todo file, and messages on the repo's todo items no longer reach it. Likewise a `.signoff` folder in a parent folder without git (not the home folder) now takes in every folder below it that has no nearer `.git` or `.signoff`. A `.signoff` that is a file or a link marks nothing.
- **A stopped inbox costs a session no Python:** once the inbox had run, even with it stopped, the hooks started Python at every prompt and turn end. Now `hook.sh` looks at `inbox.lock`'s time, which a running inbox touches every two seconds: a lock a minute old or more counts as stopped, and the hooks stop before Python, but at a session's start, resume, clear or compaction, which still notes the session and hands over messages. While no inbox runs, sessions are not kept up to date, so a session's row may be stale after the inbox starts, until that session's next prompt, tool call or turn end. An inbox started by 0.3.0 does not touch the lock, so it counts as stopped: restart it (`signoff inbox stop`, then open it again).
- **The MCP server is removed:** `mcp_server.py` and `docs/mcp.md` are gone. The plugin never registered it, and it was experimental. Agents other than Claude Code lose it; one that can run a shell command can still run the command line (see `docs/running.md`).
- **A smaller skill:** the `signoff` skill's `SKILL.md`, which loads whole each time the skill is used, went from about 17 KB to about 9 KB. The less used fields of a round moved word for word to `fields.md` beside it, and what to do once Signoff exits (the exit codes, the answers file, turning answers into actions) to `answers.md`; SKILL.md tells the agent when to read each, and now also says to put nothing secret in a board or an attachment.
- **Issue trackers:** the `signoff-inbox` skill tells the agent, in a project that keeps its tasks in an issue tracker, to copy into the todo file only the issues that wait on you, each with its link, and to keep them in step. Signoff makes no call to the tracker.
- **Fresh pictures:** the screenshots in the docs and the README's page demo show today's page, rounds in a sidebar, not tabs on top. `python3 media/demo/screenshots.py` now makes the screenshots as `record_page.py` makes the demo, and both run Signoff in a home of their own, so a running inbox on your machine no longer takes their run.
- **Short questions in chat:** the `signoff` skill tells the agent to ask a batch of up to four short questions, each text only and not sensitive (no picture, board, attachment or marks) with 2 to 4 options, with Claude Code's own question prompt instead of a page; a bigger batch, or one with a picture, still goes on the page. Your own instructions still win.
- **Rounds whose run is gone stay in the inbox:** a project's open round whose Signoff run ended (Ctrl+C, the idle timeout) or died with its session, before the round was answered, left Waiting on you at once, and nothing showed it again. Now such an orphan round stays there for up to 14 days, counted in `state.json`, the band and the Dock badge, while no live run lists it and it has no outcome file; the inbox writes its answers with the usual checks. Its row (**Run ended**) and its page say, in the round's language on the page, that the Signoff run that asked has ended and the answer goes to the project's sessions. A new run of the same rounds takes it on, under the same page. A run started just as the inbox started, whose round lock the inbox took first, now waits on the inbox instead of exiting 1.
- **The answer to such a round reaches the agent:** once every round of it is done (on its page or by another program), the inbox writes a request of the new kind `answer` in `requests/<project>/`, with the topic folder and the rounds and a fixed text of its own, none of your answers. The project's open sessions get it from the monitor, or the next session at its start, as a message that asks the agent to tell you first, then read the answers and act; `signoff inbox done <id>` closes it. The round's Done banner says so instead of "the agent has them". The `signoff-inbox` skill says what to do with it; an older plugin skips the new kind. The same request comes when a waiter stops (SIGTERM, SIGHUP, Ctrl+C) or loses its stdout just after your Done in the inbox, before it handed the answers over, or when another program finishes the rounds just after their run, a waiter or a page run, stopped or timed out: a run's entry in `runs/` now notes its exit code (`exit`), and the inbox writes the request once it lets go of rounds that are all done and whose newest run stopped (exit 130), timed out (exit 2) or died. A run whose start link was used twice (exit 1) gets none, and an entry without `exit`, from an older plugin, counts as handed over, as before.
- **Commands on an item:** an item takes an optional `commands` key, 1 to 10 of `{text, lang, caption}`, for what the user should run before deciding. The round's page shows each under the item's description as the inbox shows a code block: its language, a **Copy** button that copies the text exactly, and the hint under one that deletes with a relative path, whatever its language; Signoff never runs it. Every code block now wraps (the inbox's too). A round fails to load when a command's text starts or ends with a space or line break (a trailing one runs on paste) or has more than 4000 characters or 60 lines, or when its text, caption or language holds a known invisible or blank character (a control character other than tab and newline, a bidi override, a zero-width mark, a variation selector, the Braille blank, an unassigned code point; a caption may hold an emoji). These checks catch the known tricks; read a command before running it. The Markdown copy gives each command a line. An older Signoff refuses a round that uses the key, and so does an inbox it started (see **An inbox from before the update**).
- **Agent waits on this:** an item takes an optional `blocking` key, `true` or `false` (the default), for an item the agent's next step waits on. The round's page marks it after its title with a ■ and **Agent waits on this**, and its line in the sidebar with "agent waits", so the mark never rests on colour alone; the Summary gets a fourth filter, **Agent waits**, which shows only those items and appears only when one is marked. Any other value makes the round fail to load. The answers file and the Markdown copy do not change. An older Signoff refuses a round that uses the key, and so does an inbox it started (see **An inbox from before the update**).
- **A number item:** `"select": "number"` with a `range` key (`min` and `max`, from -10^15 to 10^15, optional `step`, default 1, and `unit`) asks for a number, such as a budget or a share, instead of made-up buckets. It has no `options`, and its `recommended`, a number in the range and on its step, is required. The round's page shows a slider and a number field that move together, the unit beside them, the recommendation preselected and tagged; a typed value between two steps goes to the nearest one when you leave the field, and the digit keys pick nothing there. The answer's `choice` is a JSON number (`0` included), `_skip` when the item is `skippable`, or `null`; every other value, NaN and Infinity among them, is refused on every save. The Summary and the Markdown copy show the value and its unit, and the Markdown copy says whether it was the recommendation. An older Signoff refuses a round that uses it, and an answers file holding a number, and so does an inbox it started (see **An inbox from before the update**).
- **A context line:** a round takes an optional top-level `context`, one line of up to 120 characters in which the agent says which session asks and what it was working on (`feat/parser session: splitting the tokenizer`). The round's page shows it as the first line of the round (on a phone in Focus, with the first item only), and its row in Waiting on you shows it after the tab and in its open row, where the search finds it. A longer value, a line break, a tab or any other control or invisible character makes the round fail to load; nothing is cut. The `signoff` skill tells the agent never to put a prompt, a transcript, a secret or a path there. The answers file, the Markdown copy, the panel's rows, notifications and `state.json` do not change. An older Signoff refuses a round that uses the key, and so does an inbox it started (see **An inbox from before the update**).
- **An inbox from before the update:** an inbox keeps running when you update the plugin, and one an older Signoff started refuses a round that uses a key it does not know (`commands`, `blocking`, `stakes`, `irreversible`, `settled`, `select: "number"`, `context`, `lines`, an attachment's `open`) or a `.diff` or `.patch` attachment, saying so only in its own log, so a run waiting on it would wait for good while you saw nothing. To keep that from happening, a waiting run checks, with an inbox from 0.4.0 or later, once that inbox has looked at the runs twice since the run started (about 5 seconds), that some process holds the round's lock: the inbox locks each round it takes in, unless another run holds it already (the inbox then shows it read only) or the file system cannot lock. A waiting run also checks its pictures and boards at start, as a page run does, so a bad one fails up front with its own error. When no one holds the lock, the run says on stderr that the running inbox did not take the round in and to restart it (`signoff inbox stop`, then `signoff inbox open`) and run the same command again, and exits 1 with nothing on stdout; the `signoff` skill has the agent tell you. An inbox that does not look at all, a round another run holds, a file system that cannot lock, an inbox started again in between (its looks count afresh) or a run whose entry in the Signoff home could not be written leaves the run waiting as before, and so does an inbox from 0.3.0, which does not touch `inbox.lock`: after updating from 0.3.0, restart the inbox yourself.
- **The Markdown copy renders nothing:** a character reference such as `&amp;`, `~~strikethrough~~`, a bare URL or `www.` address, a lone `-`, `+` or `=` line, a line such as `:-:` (a table without pipes) and a heading's closing `#` were still live in a GFM viewer, a `%%` (in `for %%f`, say) began an Obsidian comment that hid the text up to the next one, and a bidi override or zero-width character went through as it was. Now they are escaped, and a control, format or lone surrogate character shows as its code, such as `U+202E`. No Markdown escape stops two things: a GFM viewer still links an email address, and GitHub still renders its own extensions (`$math$`, `:+1:`, `@user`).
- **Stakes, cannot be undone, settled earlier:** an item takes three optional keys. `stakes` (`low`, `medium` or `high`) shows in the margin as a chip with a glyph and a word (▲ High stakes, ● Medium stakes, ▼ Low stakes), and a high one is marked in the sidebar. `irreversible`, one line of up to 200 characters saying why the decision cannot be undone, shows in the margin as **Cannot be undone** and is marked in the sidebar. `settled`, one line saying where and when the user decided it before (`round-01, 11-14`), needs `recommended`, the earlier decision: the item starts folded with that choice and a **Change** button, and counts as decided while it holds it (the inbox's panel does not wait on it). The Markdown copy gets a line for each; the answers file does not change. A bad value, or `settled` without `recommended`, makes the round fail to load. An older Signoff refuses a round that uses them, and so does an inbox it started (see **An inbox from before the update**).
- **No Vulnerabilities section:** the inbox no longer reads Uptick's `vulns.json` or `scan-repos.json`, or `osv-scanner.json` in the Signoff home, and shows no vulnerabilities: the Vulnerabilities view, its rows, Hand to agent and Scan this project are gone, and the inbox never writes Uptick's scan list. A finding you handed over from 0.3.0 or 0.4.0 that the agent has not marked done still reaches it, as before.
- **No answer from a notification:** the macOS app's notification now only says how many wait, and a click on it opens the window. Accept & send and Other answer… are gone, and so are the control socket's `offer` and `accept`: an app from 0.3.0 or 0.4.0 gets the unknown-request reply for them and shows the number, and its `open` for an older banner opens the list. Answers files with `source: "notification"`, which those versions wrote, still load, resume and show on the past-decisions page.
- **No menu bar panel:** a click on the macOS app's menu bar icon now opens the app's window, as Open Signoff and a Dock click do, instead of the inbox in a small panel under the icon. The icon keeps the number waiting beside it, and a right click still offers Open Signoff and Quit Signoff.
- **Diffs and line notes in the format:** an attachment may now be a `.diff` or `.patch` file, with the same folder, path and size rules as `.md` and `.txt`, and takes an optional `open` (`true`: its box starts open). An item with attachments takes an optional `lines` (`true`: the user may note single lines of them), and its answer then holds `lines`, at most 50 notes of `{att, line, quote, comment}`: the attachment's index, the line's number in the file from 1 (split at each line feed, a carriage return at a line's end dropped), the line's first 300 characters and the comment. A save checks each new or changed note against the file as read at start (400 otherwise); a note saved before is kept unchecked, so a file changed since never blocks a save, and a `quote` that no longer matches tells the agent the line moved. `sensitive` acts on an item with `lines`, Private hides the notes' comments, and the Markdown copy gives each note a line. The page takes the notes (see **Line notes on the page**), with a Private box on every item with `lines` (ticked at the start on a `sensitive` one). An older Signoff refuses a round with a `.diff` or `.patch` attachment, `open` or `lines`, and an answers file with `lines` (the past-decisions page shows it as a broken round), and so does an inbox it started (see **An inbox from before the update**).
- **`signoff plan`, the plan review's command:** `signoff plan --topic <YYYY-MM-DD-plan-id> --folder <decisions folder> [--resume]` takes a plan on stdin (UTF-8, the white space at its end cut, then up to 256 KiB) and puts it on a fixed round, **Plan review**: one question, Approve the plan or Ask for changes, a comment and line notes, the plan attached and open, no recommendation. It writes `plan-NN.md` and `round-NN.json` in `<folder>/<topic>/`, each created new and never through a link, after closing the topic's older open rounds with an outcome file ("replaced by round-NN"), and waits on that round beside the running inbox, then prints the answers path. The new round's number comes after every file of a round's number in the folder, so an answers file left there (as `git clean -fd` keeps the ignored ones) never answers it. With no running inbox it exits 1 and writes nothing. Without `--resume` every call is a new round; with it, the newest round is reused only when it is the fixed round, its plan is the same bytes and its answers load as a run loads them. The plugin's mod runs it when Claude Code leaves plan mode (see Plan review below); the agent never does. An inbox from before this version does not show the round: the command closes it and exits 1, saying to restart the inbox.
- **The diff view:** a `.diff` or `.patch` attachment shows on the page as numbered rows, the old and the new line's number, the sign and the text, with added and removed lines on backgrounds of their own in every palette (two new colour tokens: the palette's green and red, Rose Pine's foam and love) and their sign always shown, read out as "added" or "removed"; file and hunk headers stand apart. One that is not a unified diff shows as numbered plain text, and so does a `.md` or `.txt` attachment of an item with `lines`; others keep their plain box. A hunk counts only after a `+++` line. A file shows as plain text when it has no such hunk, when a hunk has fewer lines than its `@@` counts or a stray line inside, or when a `+`, `-` or space line comes straight after a full hunk or its `\ No newline` line (a line starting with `+++ `, `--- ` or `-- ` aside). An attachment with `open` starts open, on a round's page and on the past-decisions page. The rows are drawn when the box opens (an open box: when its round is shown), the first screen at once and the rest in chunks, so a 256 KiB file of short lines keeps the page answering.
- **No monitor, so `/restart` works:** the plugin no longer declares a monitor, whose process never ended and so made Claude Code's `/restart` refuse in every session. A message you send from the inbox (and the inbox's note on rounds finished after their run ended) now reaches an open session through the plugin's mod: it looks at the request folder of the session root's project (where the session started, or where `/cd` or a worktree move took it; a shell `cd` does not move it, as the monitor kept its project) through Claude Code's file reads, and only for a request it has not handed over runs the new `signoff inbox requests <folder> <project> <id>…`, which prints the lines as one JSON line; the mod sends them as one prompt from the plugin, which Claude Code runs as a turn of its own once the session is idle (after the turn that runs, keeping what you were typing). After an Esc, Claude Code takes no prompt from a plugin until you send something: such a message then goes at your next turn, as a turn of its own. This also works with the Waiting hint set to off, which now only hides the count. A reload of the mod sends nothing twice; after a `/clear`, a later session start with no other live session of the project hands over what still waits, as before. In `claude -p`, where the mod does not look, a message arrives only at a later session start with no other live session of the project; so do the older messages of a project the session's root moves into. The hooks note a session by its working folder, so after a shell `cd` into another project the inbox may count the session there while its mod hands over the root's project's messages. After you update, restart the inbox (`signoff inbox stop`, then `signoff inbox open`) and every open Claude Code session. On Windows, where the inbox does not run, restart the sessions. An inbox started before the update does not know this version's new keys and control requests. A session that started on 0.4.0 keeps that version's monitor until you restart the session.
- **Line notes on the page:** on an item with `lines`, each attachment row leads with the line's number in the file (in a diff, before the diff's own old and new numbers, which a phone leaves out for the text's room); pressing it (Tab, then Enter or Space) opens a field under that line with **Remove**, a second press goes back to the field, and Esc there goes back to the number. A line above the attachments says the numbers can be pressed. A field left empty saves nothing, an item takes up to 50 notes (past that the other lines' numbers are off, and that line says why), and the notes save with the round in file and line order, each with its line's first 300 characters, counted as the server counts them. A reload shows them under their lines, in a box that starts open. A note whose line is gone, or whose line's first 300 characters changed, shows under the box, read only, below "This file changed since. Line N said:" and the saved text in a box of its own, and goes back unchanged, so the save still passes; the line takes a new note. Private covers the notes, a `sensitive` item with `lines` starts Private, the Summary lists each note under its item (file, line and comment, hidden when Private), the past-decisions search finds their comments (not a Private item's), and a done round and the past-decisions page show them with nothing to press or type. In the numbered rows (a diff, or an item with `lines`), a carriage return, vertical tab, form feed, next line, line or paragraph separator inside a line now shows as `↵`, so you can see it, and a number never wraps.
- **Plan review:** while the inbox runs, a plan waits on you in Signoff when Claude is about to leave plan mode, in the main conversation of an interactive session (the terminal, the desktop app's Code tab, VS Code's panel; tried by hand in the terminal only, the other two not yet). Once you press Done the agent gets a message from the Signoff plugin, with none of your words: after Approve that exact plan goes on once (see the next entry), and the approval is used up, also when the plan is rejected; after anything else the agent reads your comment and line notes and revises. After an Esc the message goes at your next turn, with a notice that your answer is saved. `/clear`, `/resume`, quitting or restarting Claude Code, turning the Plan review setting off and a plan you approve in Claude Code's own dialog end the review. Off by default: turn it on with the new Plan review setting in `/config` (`plan`: `inbox`; any other value is off). Not with `claude -p`, not on Windows, not for a subagent's plan, not over 256 KiB, not when the session's folder or the Decisions folder setting holds an invisible format or control character. How it works: `docs/running.md`. `signoff plan` now says "cannot write in" when it cannot make the topic folder, where it blamed a link.
- **An approved plan asks no second time:** after Approve in Signoff, the mod answers Claude Code's permission request for that plan, so plan mode ends with no dialog, in the mode Claude Code picks (no mode is set): the one from before plan mode, where measured (default, accept edits and auto; bypass permissions was not tried). The Plan review round's text says so. The request names no tool call, so the mod binds it by time: the one request for the exact approved plan, from the main conversation, with only the tool's known keys, while the call it let through waits, and only when no hook beneath it (your own settings hooks, other mods) gives a decision or a block, which goes back unchanged; any other request gets Claude Code's own dialog, as does that call after a reload of the mod while it waits (the approval itself survives a reload, but not the one that turning the Plan review setting off causes), and under a managed guard that runs no `classic` hooks of a mod (not measured). After a `/cd` into another project the same plan is a new review there (Claude Code's own dialog where the inbox knows no project). An approval also needs the round's `plan-NN.md` to hold the plan the mod kept (else the answer is no approval, and a new review follows), and a resumed review takes no answer from a round its topic folder already held when the review began. A rejection in Claude Code's own dialog (not an Esc there), a prompt outside plan mode, or turning the Plan review setting off ends a kept approval, which otherwise waits as long as plan mode does. Whoever can write the answers or plan file, or get a start link of the inbox, can approve, and that now ends plan mode with no dialog.

## 0.3.0

- **The inbox:** `signoff inbox serve|open|stop` runs one local page for every project: the open rounds of runs that wait in the background, and each project's todo items. A round opens on the usual page in the same tab; Done there writes the answers file and wakes the waiting run. While an inbox is open, a run opens no page and starts no server: it waits, with no idle timeout, and exits with the same codes and stdout once the answers are done. `signoff inbox home` prints the Signoff home (exit 1 when it would not be an absolute path). The inbox needs Unix sockets, so it does not run on Windows yet. Start links come only from its control socket, `inbox.sock` in the home: each works once, within two minutes, and opens its own page.
- **One writer per round:** once an inbox has run (`inbox.lock` in the home), a run locks each open round in an empty `round-NN.json.lock` beside it, so a second run on the same round exits 1, and notes itself in `runs/` in the home (no token or link). The `.gitignore` Signoff writes now also covers `*.json.lock`. A run also notices an answers file another program finished with `done: true`, and ends as after Done on the page; a file it cannot check is not taken in and never overwritten.
- **Waiting on you:** the list opens on what waits on you, under one heading per project, oldest first or newest first (kept as `sort` in `prefs.json`), each row saying how long ago it changed. Every other open item sits behind one closed count row per project. The tab title shows the count, as `(3) Inbox`, and `state.json` in the home holds the same count, with no text. The list reloads itself when the rows change and nothing can be lost; otherwise a bar offers Reload.
- **Layout and search:** a sidebar (views, then projects), a two-line list, and the open row beside it (a bottom sheet on a phone). `j`, `k`, Enter, `f` (Focus: one item at a time), Esc and `?` work, with a key bar. A search field in the header filters every view as you type, ignoring case and accents; `/` and Cmd+K (Ctrl+K) focus it. A code block or inline code span gets a Copy button, an item gets Copy text, and a delete command with a relative path gets a warning.
- **Todo items:** the inbox reads the first of `_bmad-output/todo.md`, `TODO.md` and `todo.md` under a project's root and never writes it. An item marked `- [ ] (waiting on you: <what>) text` waits on you. An item with steps under it is one row, with "n of m steps done". A row that names an open round (`<topic folder> / round-NN`) gets **Open round**.
- **Messages to the agent:** an opened todo item takes a one-line message, and **Later** asks the agent to park the item. Each is a file in `requests/<project>/` in the home. A session open in the project gets it within seconds from the plugin's monitor; with none open, the next session start hands it over, at most ten, with a line telling the agent to tell you first. The agent marks one handled with `signoff inbox done <id>`.
- **Vulnerabilities:** when [Uptick](https://github.com/lumi-collective/uptick) keeps its `vulns.json`, the inbox shows each project's findings (package, version, level, advisory ids, fixed version) with **Hand to agent**, and never counts them as waiting. Projects Uptick does not scan are one closed *Not scanned (N)* row, each with **Scan this project**, which on your click adds the project to Uptick's `scan-repos.json` and keeps everything else in it.
- **Live sessions:** a Claude Code session waiting on you for a permission or an answer (from about six seconds after it asks) is a row in Waiting on you and counts in `state.json`; a background session gives `claude attach <id>` to copy. Sessions idle for a minute or more are listed in a dimmer **Idle** group that counts nowhere. No prompt, message or tool input is stored.
- **Appearance:** Catppuccin is the default palette; Signoff's earlier colours, Rosé Pine, Gruvbox, Tokyo Night and Dracula are built in, each tested for contrast in light and dark, and Increase contrast or forced colours give one high-contrast set. The brush button or Cmd+, (Ctrl+,) opens a picker: arrows preview, Enter keeps, Esc goes back; it also switches Comfortable and Compact. The inbox keeps the choice in `prefs.json` in the home (`theme`, `palette`, `density`, `sort`) and every Signoff page opens in it. Palette credits are in `THIRD_PARTY_NOTICES`.
- **The round's page has a new face:** the rounds sit in a sidebar with their state, and the open round's items under them. The recommendation and the cost stand in a margin beside the question. A bottom bar shows the save state, what holds Done back and **Accept this round**; `f` opens Focus, which is the default at phone width. The Summary is a sign-off sheet, and the past-decisions page uses the same sidebar, read only. Formats, routes, saving and the Done gate are unchanged.
- **Hooks and monitor:** the plugin now ships hooks and a monitor, which run in every Claude Code session. Until an inbox has run, a hook is a short `sh` script that looks for `inbox.lock` and stops, and the monitor is a shell loop that sleeps (the status line shows "1 monitor"). Hooks always exit 0 and print nothing into the session, except the hand-over of messages at a session start. After a tool call, Python starts only while some session may wait on you. Neither writes anything until the inbox has run. Monitors do not run with `claude -p`.
- **The macOS app (optional, not part of the plugin):** `app/build.sh` builds Signoff, a small app (Go, Wails) around the inbox: its page in a window, the number waiting as a Dock badge, and a menu bar item with the same number whose click opens the inbox in a 420 by 600 panel. A notification comes when the number rises. When the one round left of a run has a single open question with a recommendation, and it is not marked sensitive, the notification shows the project, round, question and recommended answer, and **Accept & send** answers it with the recommendation and Done. **Other answer…** opens that question in Focus. Notifications work only from an Applications folder. It binds no code to its webview, and quitting it leaves the inbox running.
- **Answers from a notification:** the control socket's `offer` and `accept` save the recommendation with Done and `source: "notification"` in the answers file, through the same checks as the page; the client never sends a choice. The Markdown copy says "recommendation, accepted from a notification".
- **MCP server:** with the inbox open, `signoff_open` says the questions are in the inbox, and returns no link.
- **Skills:** every open decision, and every task that waits on you, now goes on one Signoff round; `AskUserQuestion` stays for a go or skip that blocks the next step and for remote or mobile sessions, and your own instructions win. The inbox's instructions moved to a `signoff-inbox` skill, loaded only while the inbox is in play, so the always-loaded skill is shorter. The skill tells the agent to hand you the link when no browser opened, what to do when Python is missing, to mark one todo item per chain, and to give delete commands absolute paths.
- **Start link and Python:** the page and stderr now say what to do after a second click on the single-use link (still 410, exit 1). The past-decisions page says when its server has stopped. A Python older than 3.9 prints one line naming the version Signoff needs. The README says how to get Python on each OS.
- **Files that are not files:** decisions, answers and outcome files are read without blocking and must be regular files, so a FIFO where one belongs no longer hangs a run, a save, the past-decisions page or the inbox's look.
- **Past decisions:** the rounds' own text (decisions, answers, outcome) takes up to 32 MiB of the page, counted as sent; the newest topics come first, and a round past that is listed with an error that says to narrow the list with `--since`.
- **Windows:** the bare `signoff` command in Git Bash uses the `py` launcher when there is one, and stderr is written as UTF-8 on every code page. The new hooks and monitor read the same in sh and in PowerShell: without Git Bash, Claude Code runs them in PowerShell, where they do nothing (checked by hand with PowerShell 7 and Windows PowerShell 5.1). The inbox does not run on Windows yet.
- **Icon:** the plugin's listing icon is the app's mark.
- **Docs:** the README is short; the reference (the page, the file formats, running it, the inbox and the app, security, the MCP server, troubleshooting, limits, development) moved to `docs/`.
- An outcome file with a lone surrogate escape is refused when read, as decisions and answers files are.
- **Older installs:** decisions files and answers files written by 0.2.0 load as before, and the decisions file format has no new keys. An answers file with `source: "notification"` is refused by a 0.2.0 install ("cannot resume from this answers file"), so update the plugin (`claude plugin update signoff@signoff`, then `/reload-plugins`) and do not move the file away. A 0.2.0 run knows nothing of the inbox: it takes no round lock and opens its own page. The `round-NN.json.lock` files are not rounds, so 0.2.0 ignores them; where a topic folder's own `.gitignore` does not cover them they show in git as untracked files.

## 0.2.0

- **Summary:** each row quotes its comment, cut to three lines, with a **Full text** button. A filter shows **All**, **With comment** or **Not the recommendation**, each with its count. With one round open, the same list sits above a second **Done** at the end of the round; Done stays one click.
- **Private:** an item's optional `sensitive: true` starts it marked Private, and the user can tick or untick Private on any item with a comment, Other or marks. The answers file records `private: true` and keeps the text for the agent. The Markdown copy writes `(private)` in place of the comment, Other text and mark comments; the Summary shows "Private comment, hidden here." with a badge; the past-decisions search skips that text. The skill and the MCP server's `signoff_status` description tell the agent not to repeat it in a commit, its memory, a cloud service or a decision log. It is a request to the agent, not encryption.
- **Table view:** optional `criteria` on an item and `facts` on its options (`text`, and an optional `tone`, `good`, `mid` or `bad`, shown as ▲, ● or ▼ with a word for screen readers). Facts show as chips on the cards; a **Cards / Table** toggle lays the options side by side, a row per criterion, with one choice for both views. The view is not saved. On a phone the table scrolls sideways in its own box.
- **Attachments:** an item's optional `attachments` lists `.md` or `.txt` files inside the round's folder, by relative path, with an optional `caption`. They are read at start and shown as plain text in a box that starts closed; no route serves them. Up to 256 KiB each, 20 an item, 200 a round, and 2 MiB a round in the page, counted as sent (`<`, `>` and `&` take 6 bytes each); the past-decisions page holds up to 16 MiB of them. The Markdown copy names them only.
- **Paths:** the path of a picture, board or attachment is checked as text before it is resolved, on every OS. A control character, a leading `//` or `\\` (UNC, `\\?\`, `\\.\pipe`) or a drive without a root (`C:foo`) is refused. An absolute path inside the folder still works for pictures and boards. A path that cannot be resolved, such as a link loop, is an error that names the item.
- Pictures, boards and attachments are opened without blocking where the OS allows it, and must be regular files, so a FIFO cannot hang the start.
- The past-decisions page keeps going past a looping topic link and deeply nested JSON in a decisions, answers or outcome file; it lists that file with its error or warning.
- **Project name:** the header and the browser tab's title start with the project's folder name: the nearest folder with a `.git`, or the parent of a `.signoff` folder; never the home folder, never a path. The past-decisions page shows its root folder's name there.
- The past-decisions search also covers the answers: chosen options, comments, Other text, mark comments and the free text, never the text of a Private answer.
- The Markdown copy uses the round's `lang` for its labels (`en`, `hu`; any other language gets English) and leaves out an empty comment.
- The skill: when to open `--history`; a fact the user puts in a comment is recorded like one told in chat, never from a Private answer; a name or e-mail address goes into a log or commit only with the user's yes; decision log entries as decision · context · consequence; task lines start with the topic folder, the round and the item id.
- README: a Troubleshooting section. `plugin.json` says Signoff is local only. The repository moved to `github.com/lumi-collective/signoff`; `schema.json`'s `$id` follows.
- **Older installs:** decisions and answers files from 0.1.0 load in 0.2.0 as before. A 0.1.0 install refuses a round that uses `sensitive`, `criteria`, `facts` or `attachments` ("unknown key"), and an answers file with `private: true`, which 0.2.0 writes for any item the user marks Private ("cannot resume from this answers file"). Update the plugin (`claude plugin update signoff@signoff`, then `/reload-plugins`); do not move the answers file away.

## 0.1.0

First release.

- `plugin/signoff/signoff.py`: serves a decisions file, or a folder of `round-NN.json` rounds as tabs, on
  `127.0.0.1`; autosaves the answers beside each; on Done exits and prints one answers path per line. Resumes
  from existing answers files. Idle timeout (`--timeout`, default 120 minutes) with exit code 2; `--no-open`
  for SSH.
- Rounds are accepted one by one (**Accept this round**, Ctrl/Cmd+Enter), with a progress count, a ↺ mark when an
  accepted round changes, and a **Summary** tab; Done waits for every round, on the page and on the server. The
  answers file records `accepted`, `accepted_at` and `changed_after_accept`.
- Rounds: a round answered with Done is final and shows read only in later runs, so the user can look back. Done
  closes every open round at once. A broken round stops the run before anything is served, naming the file, the item
  and the field.
- The page: items with pictures and orange highlight boxes, costs, groups, single or multiple choice with the
  recommendation preselected and labelled, a comment per item, a free-text box at the end. Light and dark,
  keyboard accessible, phone width. Text and controls meet WCAG AA contrast in both themes, a Done button
  that is still waiting included.
- Security: a per-run token in the path, a single-use start link for the browser, exact `Host` check,
  JSON-only same-origin saves, size and content checks on every save, images served by index from an allowlist,
  no SVG, a nonce-based Content-Security-Policy.
- Per item, optional **Other** with a text field (`other: true`) and **Skip** (`skippable: true`), recorded as
  the choices `_other` and `_skip`.
- Keyboard shortcuts: `1` to `9` pick an option, `j` and `k` move between items, `?` lists them.
- The page's own labels in English and Hungarian, chosen by `lang`.
- Each answers file names its decisions file and that file's SHA-256.
- A second tab or window cannot overwrite newer answers: each save carries the round's save count, and an
  out-of-date save, acceptance or Done is refused with a note to reload; the reloaded page shows the newer
  answers. The server also checks the answers file is unchanged on disk, which catches a second run on the same
  folder on its next save (best effort across runs).
- Boards: an item's `images` entry may be `{"html": ...}`, the agent's own HTML shown live in a sandboxed frame
  (`sandbox allow-scripts`, under a token of its own, nothing loaded from outside) with light/dark and 1280/768/390 px switches.
- Marks: with `marks: true` the user draws rectangles on pictures, each with a comment, by pointer or keyboard;
  stored in the answers as `marks`.
- `--history <root>`: a read-only page of every past round in a project, with filters, outcomes
  (`<round>.outcome.json`), warnings when decisions changed after they were answered, `--folder`, `--since` and
  an image budget.
- A **Decisions folder** setting (default `.signoff`): where the skill puts topic folders and where the
  past-decisions page looks.
- `plugin/signoff/mcp_server.py`: an MCP server for other agents, with `signoff_open` and `signoff_status`; not
  registered by the plugin.
- A plugin icon.
- **Accept all recommendations** in the header, undoable; each answer records its `source` (`recommended`,
  `accept_all` or `user`).
- An optional `notice` in the decisions file, shown as a banner under the header.
- A Markdown copy of the answers, `<name>.answers.md`, written with every save, all text escaped.
- Writes a `.gitignore` for `*.answers.json` and `*.answers.md` into the topic folder when it has none.
- `plugin/signoff/schema.json`: the decisions file's JSON Schema.
- The `signoff` skill: when to use Signoff, where the decisions folder goes, how to batch rounds, one picture
  per option, how to run it in the background and act on the answers.
- `plugin/` is the whole plugin, with its own README and LICENSE; tests, examples and media stay outside it.
- A `signoff` command (`plugin/bin/signoff`, `signoff.cmd` on Windows) that runs the same program. The
  plugin's `bin/` folder keeps it to Claude Code on your own computer.
